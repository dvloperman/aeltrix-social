# AELTRIX Social — Prototype 0.1 (Black & Green)

واجهة اجتماعية داكنة وتجربة اتصال مباشر بين متصفحين باستخدام WebRTC DataChannel. مناسبة للنشر كملفات ثابتة على GitHub Pages.

## ما الذي يعمل في هذه النسخة؟

- ملف شخصي محلي (اسم عرض، اسم مستخدم، نبذة) محفوظ في `localStorage`.
- قائمة أسماء أصدقاء محلية فقط؛ لا يوجد بحث عالمي أو دعوات حقيقية بعد.
- اتصال WebRTC يدوي بين قرينين باستخدام نسخ Offer/Answer.
- محادثة نصية مباشرة عند نجاح الاتصال.
- WebRTC DataChannel يستخدم DTLS لتشفير البيانات أثناء النقل.

## ما الذي لا تفعله؟

- لا يوجد تسجيل دخول تقليدي أو مزامنة حسابات بين الأجهزة. الملف الشخصي المحلي ليس حسابًا عالميًا.
- لا توجد آلية لاكتشاف المستخدمين أو البحث عنهم على مستوى الشبكة.
- لا توجد رسائل مؤجلة أو تسليم عندما يكون الطرف الآخر غير متصل.
- لا يوجد تحقق تشفيري من هوية الطرف الآخر. لا تعتبر هذه النسخة آمنة للاستخدام الحساس أو الإنتاجي.
- لا يوجد خادم STUN/TURN (`iceServers: []`). الاتصال المباشر قد يفشل بين بعض الشبكات أو خلف NAT؛ لا يمكن ضمان الاتصال بين كل جهازين.
- مشاركة Offer/Answer خارج الموقع هي خطوة تمهيدية وليست نظام إشارات تلقائيًا.

## تجربة الاتصال بين جهازين

1. انشر المشروع على GitHub Pages أو شغّله عبر خادم تطوير محلي.
2. افتح الموقع في متصفحين/جهازين. HTTPS مطلوب لميزات المتصفح الحديثة، وGitHub Pages يوفّره.
3. على الجهاز A اضغط **إنشاء Offer**.
4. انسخ النص الناتج وأرسله إلى الجهاز B عبر قناة منفصلة موثوقة.
5. على الجهاز B الصق النص في حقل الإدخال واضغط **قبول Offer**.
6. انسخ Answer الناتج وأعده إلى الجهاز A.
7. على الجهاز A الصق Answer واضغط **تطبيق Answer**. انتظر حتى تصبح الحالة CONNECTED.

إذا لم يتصل الجهازان، قد تكون الشبكة أو إعدادات NAT بحاجة إلى STUN/TURN. إضافة TURN تعني الاعتماد على خادم وسيط لترحيل البيانات عند تعذر الاتصال المباشر، حتى إن بقي المحتوى مشفرًا أثناء النقل.

## النشر على GitHub Pages

1. أنشئ مستودعًا عامًا باسم `aeltrix-social` في GitHub.
2. ارفع الملفات `index.html`, `styles.css`, `app.js`, `README.md` إلى جذر المستودع.
3. افتح **Settings → Pages**.
4. اختر **Deploy from a branch** ثم `main` و`/(root)`، واضغط Save.
5. افتح عنوان Pages الذي يظهر بعد اكتمال النشر.

## تشغيل محلي

لأفضل نتيجة، شغّل الملفات عبر خادم محلي بدل فتح `index.html` مباشرةً. مثلًا باستخدام Python:

```bash
python -m http.server 8000
```

ثم افتح `http://localhost:8000`. الاتصال بين أجهزة مختلفة يتطلب HTTPS أو سياقًا آمنًا، لذا اختبر النسخة المنشورة على GitHub Pages.

## الخطوة التالية قبل اعتبار المشروع آمنًا

- إنشاء هوية بمفتاح عام/خاص وتوقيع رسائل الهوية.
- ربط هوية الطرف الآخر بالاتصال والتحقق من بصمة المفتاح عبر قناة مستقلة.
- تصميم بروتوكول E2EE مدروس للمراسلة بدل اختراع تشفير خاص.
- إضافة اكتشاف موزع للأقران، مزامنة، مكافحة إساءة الاستخدام، وحدود لحجم الرسائل.
- مراجعة أمنية واختبارات على متصفحات وشبكات مختلفة.

**ملاحظة معمارية:** GitHub Pages يستضيف الواجهة فقط. شبكة P2P بلا خوادم مركزية ممكنة من حيث المبدأ، لكن اكتشاف الأقران والتوصيل عبر NAT والتخزين أثناء انقطاع المستخدمين تبقى مشكلات منفصلة يجب تصميم حلول لها.
