# AELTRIX Social — Prototype 0.2 (Black & Green, Auto Signaling)

واجهة اجتماعية ثابتة قابلة للنشر على GitHub Pages. تستخدم PeerJS لتبادل معلومات إنشاء اتصال WebRTC تلقائيًا، بدل نسخ Offer/Answer يدويًا.

## تجربة الاتصال

1. ارفع `index.html`, `styles.css`, `app.js`, `README.md` إلى مستودع GitHub وفعّل GitHub Pages.
2. افتح الموقع على الجهاز الأول وانتظر ظهور معرّف الاتصال.
3. اضغط **نسخ رابط الدعوة** وأرسل الرابط لصديقك.
4. يجب أن يفتح صديقك الرابط بينما صفحتك ما تزال مفتوحة، ثم يضغط **اتصال بالصديق**.
5. عند نجاح الاتصال ستظهر حالة `CONNECTED` ويمكنكما إرسال الرسائل.

إذا وصل الصديق إلى الموقع دون رابط دعوة، يمكنه لصق معرّف الاتصال يدويًا في حقل معرّف الصديق. لا توجد حاجة إلى نسخ Offer/Answer.

## ما الخدمات الخارجية المستخدمة؟

- GitHub Pages: يستضيف ملفات الواجهة فقط.
- PeerJS Client من unpkg: تُحمّل مكتبة الاتصال من CDN.
- خادم PeerJS العام: ينسق بداية الاتصال ويتبادل بيانات الإشارة اللازمة لإنشاء WebRTC. لا يُفترض أن ينقل محتوى الرسائل نفسه.
- خوادم STUN عامة: تساعد المتصفحات في اكتشاف مسار اتصال مباشر.

هذا يعني أن المشروع لم يعد بلا أي خدمة خارجية؛ اخترنا خدمة تنسيق لتسهيل تجربة الاستخدام. قد تتعطل الخدمة العامة أو تكون محدودة، وهي ليست ضمانًا لتوافر دائم. بعض الشبكات تمنع الاتصال المباشر وقد تحتاج TURN، وهو خادم وسيط يرحّل بيانات الاتصال.

## ما الذي يعمل؟

- ملف شخصي محلي محفوظ في `localStorage`.
- قائمة أسماء أصدقاء محلية فقط.
- معرّف PeerJS مؤقت ينشأ تلقائيًا عند فتح الصفحة.
- رابط دعوة يملأ معرّف الصديق تلقائيًا.
- اتصال WebRTC DataConnection ومحادثة نصية مباشرة عند نجاح الاتصال.

## الحدود الأمنية والوظيفية

- المعرّف مؤقت وقد يتغير عند إعادة تحميل الصفحة؛ يجب أن تبقى صفحة صاحب الدعوة مفتوحة كي يكون متاحًا.
- لا يوجد تسجيل حسابات عالمي، ولا بحث عالمي عن المستخدمين، ولا رسائل مؤجلة أو تخزين دائم للمحادثات.
- WebRTC يشفر النقل بين الطرفين، لكن هذا النموذج لا يثبت تشفيريًا أن الطرف المتصل هو الشخص الذي يدّعيه. لا تستخدمه لمعلومات حساسة ولا تعتبره منتجًا أمنيًا جاهزًا.
- خادم التنسيق يرى بيانات الاتصال اللازمة للإشارة مثل معرّفات الأقران وبيانات الشبكة الوصفية؛ لا تفترض أن خدمة عامة بلا سجلات أو ضمانات خصوصية.
- هذا نموذج أولي تعليمي؛ يحتاج مراجعة أمنية واختبارات متعددة قبل الاستخدام العام.

## النشر على GitHub Pages

1. أنشئ مستودعًا باسم `aeltrix-social`.
2. ارفع الملفات الأربعة إلى جذر المستودع.
3. افتح **Settings → Pages**.
4. اختر **Deploy from a branch** ثم `main` و`/(root)` واضغط Save.
5. افتح رابط Pages بعد اكتمال النشر. يلزم اتصال بالإنترنت لتحميل PeerJS واستخدام خدمة التنسيق.

## خطوات لاحقة مقترحة

- إنشاء هوية بمفتاح عام/خاص وتوقيع بيانات الهوية.
- التحقق من هوية الصديق عبر بصمة مفتاح ثابتة.
- تصميم بروتوكول مراسلة E2EE مدروس بدل الاعتماد على تشفير النقل وحده.
- اختيار خدمة TURN موثوقة عند الحاجة، مع فهم أنها قد تمرر حركة البيانات.
- بناء آلية بحث واكتشاف أقران وتخزين/مزامنة إذا أردنا شبكة اجتماعية فعلية.
